CASE 01 · 장애 해결 · 성능

SQL 성능 개선으로 매월 반복되던 서버 다운 제거

월간 서버 다운 → 해소 재시작으로 넘기던 반복 장애를 근본 원인 해결로 마무리
상황
운영 중인 서비스에서 특정 SQL의 성능 문제로 서버 부하가 쌓이면서, 매월 서버가 다운되는 장애가 반복됐습니다.
역할
장애 원인 분석, SQL과 조회 로직 개선
원인 분석
서버 재시작으로는 일시적으로만 복구될 뿐 재발을 막을 수 없다고 판단했습니다. SQL 실행 구조와 조회 로직을 분석해 서버 부하의 원인이 되는 병목 구간을 찾아냈습니다.
해결
병목이 된 쿼리의 구조와 조회 로직을 개선해 실제 데이터량과 트래픽에서도 부하가 쌓이지 않도록 했습니다.
결과
반복되던 월간 서버 다운 문제를 제거하고 서비스를 안정화했습니다.
직무 연결
운영 시스템에서는 기능이 동작하는 것만큼, 데이터 증가와 실제 트래픽을 견디는 성능 설계가 중요하다는 것을 배웠습니다. 그룹사 시스템의 장애를 일시 조치에서 끝내지 않고 근본 원인까지 해결하겠습니다.

상황

판단

해결
현업의 처리 흐름을 단계별로 분석해 누락이 생기는 지점을 찾고, 반복되는 확인·처리 작업을 시스템이 맡도록 자동화 로직을 적용했습니다.
결과

직무 연결
현업 사용자의 업무 흐름을 이해하고 반복 작업과 휴먼 에러를 시스템으로 줄이는 일은 그룹사 업무 시스템 운영과 수출물류 프로세스 개선에서 핵심이라고 생각합니다.

IP 접근 제어 기능 개발과 운영 보안 요구사항 대응

요청 단계 IP 차단 구조 구축 개인정보·본인인증을 다루는 대국민 서비스의 접근 통제 강화
상황
개인정보와 본인인증을 다루는 대국민 서비스인 만큼, 비정상 접근을 통제하고 운영 환경의 보안 요구사항에 대응해야 했습니다.
역할

기술적 판단
차단 대상 IP를 코드에 고정하지 않고 DB에서 관리하도록 하고, 웹 요청 단계에서 이를 확인해 애플리케이션 로직에 닿기 전에 접근을 막는 구조로 설계했습니다.
해결

결과
차단 대상 관리와 접근 제어를 서비스 안에서 처리할 수 있게 되었고, 개인정보 보호 요구사항을 기능 단위로 반영했습니다.
직무 연결
